# Гайд деплою під ключ — Railway

Покрокова інструкція від нуля до працюючого бота. Час: ~20-30 хвилин.

---

## Крок 0. Що потрібно мати заздалегідь

- [x] Токен бота від @BotFather
- [x] Google Cloud сервісний акаунт (JSON-ключ)
- [x] Gemini API ключ
- [x] Google-таблиця в папці SigmaFoodRezerv
- [ ] Акаунт на railway.app (безкоштовний, вхід через GitHub)
- [ ] Акаунт GitHub (для завантаження коду)

---

## Крок 1. Підготувати Google-таблицю

1. Створіть **одну** Google-таблицю в папці SigmaFoodRezerv (назва будь-яка, напр. «SigmaFood DB»).
2. Аркуші **створювати вручну не треба** — бот зробить їх сам при першому запуску
   (База_Меню, Довідник_Користувачів, База_замовлень, Для кухні).
3. Скопіюйте **ID таблиці** з URL:
   `https://docs.google.com/spreadsheets/d/`**`ЦЕЙ_ДОВГИЙ_ID`**`/edit`
4. **Найважливіше:** відкрийте доступ таблиці для сервісного акаунта.
   - Натисніть «Поділитися» (Share).
   - Вставте email сервісного акаунта (виду `...@...iam.gserviceaccount.com` — він є у JSON-ключі, поле `client_email`).
   - Дайте право **Редактор**.
   - Те саме зробіть для всієї папки SigmaFoodRezerv.

> ⚠️ Без цього кроку бот не зможе писати в таблиці — це причина №1 помилок.

---

## Крок 2. Дізнатись свій Telegram Chat ID (для адміна)

1. Напишіть боту @userinfobot у Telegram.
2. Він відповість вашим числовим ID — це `ADMIN_CHAT_ID`.

---

## Крок 3. Завантажити код на GitHub

1. Створіть новий приватний репозиторій на github.com.
2. Завантажте туди всі файли проєкту (папки `app/`, `webapp/`, файли
   `requirements.txt`, `Procfile`, `runtime.txt`).
   Можна через веб-інтерфейс GitHub («Add file» → «Upload files»)
   або через git:
   ```
   git init && git add . && git commit -m "SigmaFood"
   git remote add origin <URL_вашого_репо>
   git push -u origin main
   ```

> ⚠️ Файл із JSON-ключем сервісного акаунта **НЕ завантажуйте** в репозиторій.
> Він піде окремо у змінні оточення (крок 5).

---

## Крок 4. Створити проєкт на Railway

1. Зайдіть на railway.app → «New Project» → «Deploy from GitHub repo».
2. Оберіть свій репозиторій. Railway автоматично визначить Python.
3. Дочекайтесь першого білду (він впаде через відсутні змінні — це нормально, далі виправимо).

---

## Крок 5. Додати змінні оточення

У проєкті Railway → вкладка **Variables** → додайте:

| Змінна | Значення |
|---|---|
| `BOT_TOKEN` | токен від @BotFather |
| `GEMINI_API_KEY` | ваш ключ Gemini |
| `GOOGLE_CREDENTIALS` | **весь вміст JSON-файлу** сервісного акаунта, одним рядком |
| `SPREADSHEET_ID` | ID таблиці з кроку 1 |
| `ADMIN_CHAT_ID` | ваш Chat ID з кроку 2 |
| `BASE_URL` | поки залиште порожнім — заповните в кроці 6 |

> Для `GOOGLE_CREDENTIALS`: відкрийте JSON-файл, скопіюйте **весь** вміст
> (від `{` до `}`) і вставте як значення. Railway приймає багаторядкові значення.

---

## Крок 6. Отримати публічний домен і дозаписати BASE_URL

1. Railway → вкладка **Settings** → розділ **Networking** → «Generate Domain».
2. Отримаєте URL виду `https://sigmafood-production.up.railway.app`.
3. Поверніться у **Variables** і впишіть цей URL у `BASE_URL`
   (без слеша в кінці).
4. Railway автоматично перезапустить сервіс.

---

## Крок 7. Перевірка

1. Відкрийте вкладку **Deployments** → лог має показати запуск без помилок
   і рядок про встановлення webhook.
2. Напишіть боту `/start` — як адмін ви побачите меню адміністратора.
3. Відкрийте Google-таблицю — у ній з'являться 4 аркуші з заголовками.

Якщо `/start` не відповідає:
- перевірте, що `BASE_URL` правильний і без слеша в кінці;
- перевірте лог Railway на помилки доступу до Sheets (крок 1.4).

---

## Крок 8. Перший робочий сценарій

1. **Адмін** надсилає боту PDF-меню → бот парсить і зберігає (без «Полуденка»).
2. **Адмін**: `/add_teacher Іванова Марія | 3-А | <chat_id вчителя>`.
3. **Вчитель** пише боту `/start`, потім:
   `/add_student Петренко Іван | 3-А | <chat_id мами> | <chat_id тата>`.
4. **Адмін**: `/broadcast Просимо обрати харчування на тиждень`.
5. **Батьки** відкривають кнопку Web App, обирають страви, зберігають.
6. **Вчитель** отримує сповіщення про підтвердження.
7. **Адмін**: `/report` → отримує .xlsx для кухні.

## Обслуговування

- **Логи**: Railway → Deployments → View Logs.
- **Оновлення коду**: `git push` у репозиторій → Railway передеплоїть автоматично.
- **Зміна тижня**: система використовує ISO-номер тижня автоматично за датою.
  Нове меню на наступний тиждень завантажується новим PDF.

## Відоме обмеження

Google Sheets як БД підходить для однієї школи. За великої одночасної
активності о 00:00 можливі затримки API. Для масштабування на кілька шкіл
варто мігрувати на PostgreSQL (структура даних уже сумісна — ті самі поля).

## Усунення несправностей

### Помилка: `No GitHub artifact attestations found for python@3.12.6`

Це збій збірщика Railpack/`mise` під час перевірки атестацій Python — **не помилка коду**.

**Що вже виправлено в проєкті:**
- Прибрано `runtime.txt` із жорсткою версією `3.12.6`.
- Додано `.python-version` зі значенням `3.12` (гнучка версія).
- Додано `railpack.json` із явною конфігурацією збірки.

**Якщо помилка все одно повторюється** — вимкніть перевірку атестацій.
Railway → **Variables** → додайте змінну:

| Змінна | Значення |
|---|---|
| `MISE_PYTHON_GITHUB_ATTESTATIONS` | `false` |

Після додавання зробіть **Redeploy** (Deployments → три крапки → Redeploy).

### Помилка доступу до Google Sheets у логах

`PermissionError` або `403` → сервісний акаунт не має доступу до таблиці.
Поверніться до **Кроку 1.4** і надайте йому право «Редактор».

### Бот не відповідає на /start

- Перевірте, що `BASE_URL` збігається зі згенерованим доменом і **без слеша** в кінці.
- Перевірте лог Deployments на рядок про встановлення webhook.

### Помилка: `Failed to build an image` на етапі Build

Якщо збірка падає швидко (10-20 сек) на «Build image» — майже завжди
це `pip install`, що не зміг поставити якусь версію із `requirements.txt`.

**Що вже виправлено:** усі версії бібліотек у `requirements.txt` оновлено
до актуальних і перевірено на сумісність (зокрема `google-genai`, який
раніше був вказаний застарілою версією).

**Якщо повториться** — відкрийте **Build Logs** (не Deploy Logs) і знайдіть
рядок `ERROR: Could not find a version...` або `No matching distribution`.
Він назве конкретний пакет. Надійшліть його — версію можна підняти.

### Конфлікт конфігурації запуску

У проєкті команда запуску задана **лише** в `railpack.json`
(`Procfile` навмисно прибрано, щоб не було двох джерел істини).
Не додавайте `Procfile` назад.
