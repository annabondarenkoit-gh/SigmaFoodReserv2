# Покриття тестових кейсів (UAT)

Відповідність кожного кейсу ТЗ реалізованому коду.

| ID | Сценарій | Де реалізовано | Як перевірити |
|----|----------|----------------|---------------|
| **TC-01** | Парсинг PDF-меню без «Полуденка» | `gemini_parser.py` (промпт + захисна фільтрація за `CATEGORIES`), `handlers` → `handle_pdf` | Адмін надсилає PDF → бот пише, скільки страв витягнуто; «Полуденок» відсутній у База_Меню |
| **TC-02** | Керування учнями класу | `handlers` → `cmd_add_student`, `sheets.add_student`; перевірка `клас == data['клас']` | Вчитель додає учня свого класу — успіх; чужого — відмова |
| **TC-03** | Вільний вибір страв батьками | `webapp/index.html` (чекліст без ліміту), `main.py` → `api_order`, `sheets.upsert_order` (JSON-масив) | Батьки обирають 2 сніданки + 1 обід → один рядок у База_замовлень із JSON |
| **TC-04** | Дедлайн 00:00 | `deadline.is_locked_for_parents`, перевірка в `api_order` (HTTP 423), замок у Web App | Спроба редагувати поточний день → «День закрито», запис не змінюється |
| **TC-05** | Коригування персоналом + червоний колір | `is_staff_modified` у База_замовлень, підсвічування `.dish.staff` у Web App | Змінена персоналом страва підсвічується червоним у батьків |
| **TC-06** | Сповіщення вчителю | `notify.notify_teacher_confirmation`, виклик у `api_order` лише при першому підтвердженні | Батьки зберігають меню → вчитель отримує «✅ ... обрали меню на ...» |
| **TC-07** | Звіт .xlsx для кухні | `report.build_report` (2 листи), `sheets.rebuild_kitchen`, `handlers` → `cmd_report` | Адмін: `/report` → .xlsx із точним підрахунком порцій кожної страви |

## Примітки до реалізації

- **Порції двох вікових груп** (`120г // 140г`) не зберігаються — за рішенням замовника
  беруться лише назви страв.
- **Алергени** (МП, Г, Я, Р, А) витягуються Gemini й показуються батькам у Web App.
- **Два контакти батьків** мають спільний доступ до одного вибору дитини.
- **Аркуш «Для кухні»** перераховується автоматично з База_замовлень — вручну не редагується.
